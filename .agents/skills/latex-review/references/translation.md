# 翻译变更内容

用户要求翻译时，按实际配置核对接口、术语表、缓存和导出行为。已有报告可直接使用；旧报告缺少 **translation-units.json** 时，先按正确来源重新生成到专用报告目录。源码对比回退报告不提供结构化翻译候选，按能力未完成记录。

1. 核对报告中的翻译候选与用户要求的范围。当前翻译修改前后两版中**包含变化的完整段落**，以及变更标题和图注；新增或删除只处理存在的一侧。段内未修改句子也有译文，但仅变化句子沿用原文标记。未变化段落、表格、独立公式、参考文献条目和源码注释不进入翻译。
2. 核对全局与项目合并后的 **[translation]** 配置：全局文件为 **~/.config/latex-review/config.toml**，设置 **XDG_CONFIG_HOME** 时使用其对应目录；项目字段优先，术语表合并且同名词条以项目值为准。**--config** 选择项目层文件，全局默认值仍会读取。确认最终接口地址、模型、密钥环境变量名和术语表；带注释的空模板尚未启用翻译。密钥缺失时，请用户在启动服务的终端设置该环境变量；配置和聊天中使用环境变量名，不收集、打印或写入实际密钥。配置字段以本机配置模板及 `latex-review-preview --help` 为准。
3. 先用 **latex-review-local list** 发现并复用已有本机服务；尚未启动时，按 [审阅参考](review.md) 中的预览步骤启动并打开实际地址。通过“翻译此处”操作用户选定的主变更；只有用户要求处理整份报告的候选时，才使用“翻译全部变更”。**批量按钮不受当前筛选条件限制**。直接打开静态文件可以阅读已导出的译文，新的翻译请求需要本机服务。
4. 观察逐项进度与结果，切换英中对照；核对完整段落的句子对应、修改前后侧别、术语、限定条件、否定、数值、公式与引用，以及变化的中文句子能否定位对应原文。新增、删除、拆句或合句存在时检查相应侧别和句组。中文沿用英文差异判定与统计，译文用于辅助阅读，不回写论文源码。
5. 保留已成功译文，按用户范围重试失败项。使用“停止翻译”时确认待发送任务停止；已发送请求可能继续完成并产生费用。超时、限流或无效输出按实际状态记录，不把原报告可读当作翻译成功，也不无限重试。
6. 缓存位于报告目录同级的 **translation-cache/**，可通过 **--translation-cache-dir** 指定独立目录。模型、接口、规则或术语表改变后，重新启动服务并核对当前配置的结果。区分缓存复用、模拟接口验收与真实 API 调用；缓存命中和模拟测试均不能证明当前真实服务已联调成功。
7. 译文作为交付结果或需要分享时，使用“导出含译文报告”保存到专用路径，直接打开导出文件验证译文及阅读资源。导出保留已完成译文，不包含 API 密钥或本机服务会话令牌；公式排版沿用原报告在线依赖，不能称为完全离线报告。验收完成后只停止本次新建槽位，保留此前已有服务。提供有效文件路径；工作端口停止后失效，稳定入口仍可用于发现和恢复。

记录翻译成功、失败、尚未处理和当前不支持的内容，以及英中切换、句子定位和导出的实际验收结果。未配置服务、缺少密钥或浏览器访问受限时，保留原文审阅结果，明确翻译验收未完成。
