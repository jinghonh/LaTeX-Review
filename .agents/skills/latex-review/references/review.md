# 运行审阅

1. 先确认用户要求修改的章节、文件和对比基线。查看 **git status --short** 与 **git diff --name-status HEAD**。默认来源是磁盘工作区，包含暂存及未暂存的已跟踪修改和未忽略的未跟踪文件；其中也可能有本轮之前的工作。
2. 用 **command -v latex-review** 确认命令行工具已安装。如果找不到，说明可在 Python 3.11 或更新版本的环境中运行 **python -m pip install /path/to/LaTeX-Review** 安装本工具。不要自行安装软件或修改论文源文件。
3. 按用户给出的来源选择模式。常用的 Git 模式为：

~~~sh
latex-review main.tex --output .latex-review/latest
~~~

指定 Git 版本可添加 **--old REV --new REV**；新版可用 **worktree** 表示当前磁盘工作区。目录模式使用 **--old-dir OLD --new-dir NEW --entry path/to/main.tex --output REPORT_DIR**；两个独立文件使用 **latex-review OLD.tex NEW.tex --output REPORT_DIR**。为避免报告混入来源内容，建议目录模式把报告输出放在两个输入目录之外。

4. 运行时记录退出码和标准错误。工具会先替换所选报告目录，只在专用报告目录中输出文件；若该目录已有用户文件，改用新的输出路径。默认不传 **--compile**。
5. 先检查本次进程退出码，再读取 **run.json** 中的实际基线、阶段状态和降级原因。无效参数或配置可能保留旧清单。若 **diff.json** 存在，用 **latex-review-query REPORT_DIR** 分页读取主变更，按需用 **--change-id ID --include-raw** 读取原文；旧安装没有查询命令时直接读取 JSON。用户指定文件范围时，用 **latex-review-check-scope REPORT_DIR --allow PATTERN** 核对；章节范围仍由智能体核对。无论是否有差异文件，都独立读取存在的 **diagnostics.json**，检查每项诊断的严重级别、代码、说明和源码位置；来源失败时也阅读标准错误。对照用户指定范围、Git 变更清单及删除路径，指出超范围修改、删除、缺失依赖、源码定位不确定和需要判断的警告或错误。
6. 仅当用户要求页面验收，或任务涉及报告界面时，执行浏览器验收。若存在 **report.html**：用 **latex-review-preview REPORT_DIR** 启动预览，保存本次进程或终端会话标识，并读取标准输出中的实际 HTTP 地址。命令不可用时，可在已安装本项目的同一 Python 环境运行 **python -m latex_review.serve REPORT_DIR**。服务自动读取用户全局翻译默认值，再叠加启动目录的项目配置；从其他目录启动且论文有局部设置时，以 **--config CONFIG_PATH** 指向该论文配置。服务就绪后，用可用且允许访问本机网页的浏览器工具打开该地址。启动服务本身不调用翻译 API。
7. 核对页面内容与机器数据，查看实际渲染截图，检查图片、公式及错误提示；对报告中存在的筛选、阅读范围、主变更导航和句子明细跳转各执行一次，确认双侧整句着色与实际落点。分别记录通过、失败和未完成的项目；句子锚点缺失时按定位未完成记录，不能把段落高亮当作句子定位成功。用户要求翻译时，在停止本次服务前执行下述翻译分支，再进入清理步骤。外部编辑器协议跳转独立记录。若工具缺失或访问被禁止，保留机器数据检查结果，明确将渲染和交互验收标为未完成；遵守工具限制，不通过更换地址或工具规避访问禁令。
8. 执行浏览器验收时，保存实际结果和已有截图等证据文件。执行了验收且存在本次 **run.json** 时，用 **latex-review-record-acceptance REPORT_DIR --status STATUS --evidence FILE** 记录实际结论；**STATUS** 选择 **passed**、**failed** 或 **incomplete**。该命令只保存声明。证据不足或工具受限时记录 **incomplete**。验收成功、失败或中断后，都在清理步骤中停止本次启动的服务：向保存的终端会话发送 Ctrl+C，或仅向本次进程发送终止信号，并确认进程退出。用户明确要求继续预览时才保留。服务已停止时，说明临时地址已失效。
未执行浏览器验收时，说明“未执行”，不生成验收记录。

9. 向用户提供 **report.html** 的完整路径及报告目录，简述主变更、诊断、范围、删除检查结果及浏览器验收完成情况；执行了翻译时，同时交代译文覆盖、失败项、缓存复用和导出结果。支持本地文件链接时链接报告入口。

查询条件、分页及原文展开参数以 `latex-review-query --help` 为准。查询返回全报告摘要；筛选结果不能代替对全部主变更的核对。

旧安装没有查询命令时，直接读取本次 JSON 数据。


## 退出码与诊断

- **0**：完整报告已生成。仍须核对变更与诊断；该退出码不代表修改通过人工审阅。
- **2**：报告已生成，但含警告或错误诊断，也可能是降级解析或源码对比回退。读取两个 JSON 文件并说明限制，不要称为无异常审阅。
- **4**：输入来源无法读取。修复入口、提交或依赖问题；目录中可能只有失败诊断，没有完整报告。
- **8**：命令行内部错误。保留错误输出并说明审阅未完成，不要把部分文件当作完整报告。
- **64**：参数或配置无效。修正命令或配置；例如仅编译新版本或沙箱渲染选项须同时启用编译。

仅含 **info** 诊断时退出码可能仍为 0，应按任务上下文阅读。任何退出码都不能代替对报告内容的判断。


## 能力边界

当前正式支持 macOS，要求 Python 3.11 或更新版本。报告是内容预览，不保证最终排版；阅读页面显示可预览内容与简短占位，详细诊断留在机器数据中。公式展示使用联网 MathJax；不可用时原位显示“此处暂无法预览”。简单表格可比较并定位确定的单元格、行列变化，复杂表格保留整体变化与不确定性。同路径图片文件的字节指纹变化可形成图明细，不能据此断言视觉内容变化。正文按段落等独立结构计主变更，句子作为内部明细展示双侧完整内容和对应定位。若输入文件被删除，Git 状态可能记录删除，但缺失依赖会妨碍常规结构比较；同时报告 Git 删除和相关诊断。

仅在用户明确要求时使用 **--compile** 进行整篇 LaTeX 编译；默认审阅不编译整篇，也不自动安装 TeX。报告生成可按需调用已有 TeX 环境制作复杂片段预览，失败时保留报告并在原位显示“此处暂无法预览”。显式整篇编译在隔离副本中运行，缺少工具或某侧失败时保留报告并返回 2；来源读取失败仍返回 4。可用 **--compile-new-only** 只编译修改后版本；需要复杂宏受限渲染时再显式启用 **--sandbox-render**。完整编译选项以 `latex-review --help` 为准。

源码位置始终属于对应比较版本。分享时使用单文件报告或完整报告目录。
