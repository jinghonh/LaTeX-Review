# 批注性能验收记录

日期：2026-10-14。结果：所有最终验收场景 P95 均低于 200 毫秒。

## 测量边界

端到端耗时从客户端调用提交开始，到持久化成功、页面更新及两个动画帧之后结束。实际保存按钮另行测量。
每组测量 40 次。P95 使用最近秩法。提交速率最多每秒五次，包含准备及清理请求。
种子数据为 9900 条线程和 100 个正文版本；新增 100 条时达到 1 万条可见线程。每轮清理测试线程并保留删除历史。
测试使用当前真实论文的全部正文及原批注副本；新增规模数据分散在不同正文单元。
所有性能测试最终串行执行。原始失败记录保留在本地性能目录；并行测试和持续增大可见线程的旧脚本不作为最终验收。

## 正式服务与数据

正式迁移保留 141 条线程、219 条消息、33 个正文版本和修订号 276。
迁移前后逐项比较全部公开备份数据及请求收据，结果完全一致。旧 JSON 保留为 `.json.migrated`。
两个服务槽位均恢复到 ready，实际浏览器检查均通过。稳定链接保持原值。
最终存储仍为 141 条线程，其中 132 条未删除、9 条保留删除历史；修订号仍为 276。逐条比较线程与迁移备份，结果一致。
差异报告的旧内嵌脚本已同步更新。性能测试没有向正式存储添加测试批注。

正式服务修订号查询中位数为 15.0 毫秒，P95 为 26.9 毫秒。原查询实测约 1.24–2.38 秒。
该次查询后的正式持续预览工作进程 RSS 为 59.7 MiB；这是一次采样，不是峰值。

## 计算资源口径

原单条后端测量消耗约 10.96 CPU 秒，且重复恢复和打包全部历史。新测量只读取受影响线程，历史版本不进入普通写入路径。
原始结果包含各场景测试进程 CPU 总时间和起止 RSS。该进程也承担准备、清理及测试通信，因此这些值不是纯单次事务资源。
完整迁移、正文准备、备份及导出仍可能占用较多内存。它们按确认范围单独计时。

## 验证与复现

核心回归 139 项通过，浏览器回归 34 项通过。额外 gzip/正文引用测试包含在核心验收中。
核心回归覆盖事务回滚、提交失败的源码补偿、单条及批量幂等、预检失效、并发冲突、迁移、历史导出及版本对象独立性。
浏览器回归覆盖卡片状态、筛选、草稿、离线导出及导入、外部增量更新和源码建议。
额外浏览器测试确认 gzip 批量请求及正文引用恢复。

原始数据：`.latex-review/performance/acceptance-final.json` 和 `acceptance-ui-concurrency.json`。
复现脚本：`scripts/benchmark-annotations.py`。先运行 `--help`。安装测试依赖后指定本机报告目录和输出路径。
