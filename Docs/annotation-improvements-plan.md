## 已确认的行为

1. 全部建议分阶段实现。普通 LaTeX 原文可定位包含行内公式的选区。公式内容参与校验，支持确定等价的包装和空白规范化；保留 U+FFFC 输入。新建批注的近似匹配只提供候选，不自动写入，不改变换版迁移规则。
2. 匹配失败返回有限的相近片段、编辑距离、上下文和源码位置。歧义匹配要求调用者明确选择。候选不能作为成功定位的替代品。
3. 高层 CLI 写入默认只返回成功状态、线程 ID、消息 ID、版本号和请求 ID，并提供完整结果选项。底层 JSON/HTTP 接口保持兼容。读取支持筛选、字段选择及分页，不截断 JSON 或用于定位的原文。
4. 批量操作复用单条校验，一次加载正文、一次加锁和一次持久化。默认提交成功项，并返回全部逐条结果；提供预检和显式整批原子模式。支持批量添加与回复。
5. 调用者提供唯一请求 ID。相同 ID 与相同内容重试返回原结果；相同 ID 与不同内容返回冲突。幂等记录与批注写入共同持久化。
6. 批量复核保存开始时线程清单及修订号，核对遗漏、重复回复、父消息和作者。运行期间新增批注单独报告。发生版本冲突时重新读取，不自动重复已成功操作。
7. 复核回复包含判断、依据、剩余问题。判断为“已落实、采纳、部分采纳、不采纳、证据不足”。回复完成不等于问题解决；证据不足时保持未解决。
8. 简单浮动体提供图注、表头、单元格子单元及精确源码位置。复杂宏、嵌套和跨行跨列结构允许明确降级。源码定位不可靠时不能自动回写。浮动体仍是一个主变更，子单元不重复计数。
9. 建议保存原始 LaTeX 块和替换 LaTeX 块。CLI 和 Web 提供差异预览及显式应用。仅允许可靠、连续、单文件的源码区间；验证原文及源码版本，过期建议拒绝应用。
10. 应用成功记录“已应用”，不自动解决批注。新报告保存重建配方并固定旧版来源。可写新版自动更新，Git 历史提交只读。先在临时目录重建，成功后切换；失败保留原报告并显示“源码已修改、报告待更新”。旧报告缺少配方时允许显式应用，说明无法自动更新的原因。
11. 技能补充精简读取、可靠批量复核、应用建议及通过服务端口定位报告目录的方法。普通审阅和翻译仍不隐式回写源码。
