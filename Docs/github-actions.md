# GitHub 拉取请求审阅产物与评论

此功能是可复制的工作流模板，不会随工具仓库的现有工作流自动运行。初版只在 GitHub 的 `macos-latest` 执行环境使用；没有 Linux 支持承诺。

## 显式启用

1. 在论文仓库中复制 `examples/github/latex-review-pr.yml` 和 `examples/github/latex-review-comment.yml` 到 `.github/workflows/`。只需产物时可只复制前者。
2. 在两个文件中把 `REPLACE_WITH_TRUSTED_TOOL_COMMIT` 替换为经审阅的 LaTeX Review 完整提交标识，两个文件必须相同；此提交须包含 `latex_review.ci` 和 `latex_review.ci_comment`。不要改为拉取请求的分支名。工具仓库需允许论文仓库读取该提交。
3. 把审阅工作流中的 `--entry main.tex` 改为论文实际入口。确认该仓库的 Git 历史中，拉取请求的基准与新版本都包含入口及其依赖。按需调整 `retention-days: 14`，但不能超过仓库或组织的产物保留上限。
4. 检查论文仓库的 Actions 运行许可、产物可见范围及 `GITHUB_TOKEN` 权限设置。评论工作流需 `actions: read`、`issues: write`、`contents: read`；若组织策略不给写权限，产物仍可交付，评论会跳过并给出提示。若论文内容保密，应先确认谁能下载 Actions 产物，再启用工作流。

启用后，`pull_request` 的打开、同步或重新打开事件触发审阅。旧版固定为事件中的 `pull_request.base.sha`，新版固定为 `pull_request.head.sha`，不使用随运行时间变化的 `HEAD` 或磁盘工作区。审阅工具从固定提交安装；论文签出在只读作业中，作业不给密钥或写权限。来自分叉的请求也在此作业生成产物。评论工作流由审阅工作流的完成事件触发，使用默认分支上的可信工作流和同一固定工具提交，不签出、安装或执行请求中的代码。分叉请求直接跳过评论。

## 产物与状态

每轮上传 `latex-review-report` 与 `latex-review-status`，均保留 14 天，除非维护者修改模板。报告产物是**整个报告目录**：可用时包含 `report.html`、`diff.json`、`diagnostics.json` 以及存在时的 `assets/`、`previews/`；失败时可能只有 `diagnostics.json`。状态产物只有固定字段的 `status.json`，包括退出码、完整报告是否可用、主变更数、正文增删词数与分类命中数，不包含论文原文、诊断文字、源码路径或本机绝对路径。报告和机器数据都可能含论文内容，应按论文仓库的访问策略保护。

| 审阅退出码 | 产物 | 作业结果 |
| --- | --- | --- |
| `0` | 完整报告与状态 | 通过；仍需阅读报告，不能视为论文修改已获验收 |
| `2` | 降级报告、机器数据与状态 | 失败；报告仍可下载，评论明确标注降级 |
| `4` | 可能只有失败诊断与状态 | 失败；来源无法读取 |
| `8` | 可能只有失败诊断与状态 | 失败；内部错误 |
| `64` | 可能只有失败诊断与状态 | 失败；参数或配置错误 |

上传步骤先于最终状态判定，因此 `2/4/8` 不会伪装通过，也不会因作业失败而丢失可检查的产物。如果报告产物缺失，发布器不会写评论。评论只包含固定统计字段、降级说明和当前运行的产物链接；它用稳定标识更新同一请求的已有机器人评论，不引用诊断消息或来源标识。产物过期后，旧评论中的链接也会失效；下一轮运行会更新链接。无写权限时记录跳过原因，不请求额外凭据，也不提升权限重试。

## 安全边界

`pull_request` 作业的权限仅为 `contents: read`，签出时不保留凭据。评论工作流虽然有写权限，但只读取 GitHub 事件和状态产物中的严格校验字段，不执行报告内容或请求代码。请勿将评论工作流改为在 `pull_request_target` 下签出并运行请求代码，也不要把审阅作业改成写权限。模板本身允许维护者显式配置后才会启用。

仓库现有 `.github/workflows/macos.yml` 仅验证工具自身，不发布论文产物或评论。
