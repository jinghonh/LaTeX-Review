# 报告批注规格

用户于 2026-10-10 通过 grilling 访谈确认本规格，并授权分阶段子对话实现。

规格工单：https://github.com/jinghonh/LaTeX-Review/issues/48。

## 用户确认的行为

1. 修改后版本的全部正文可批注，包括没有发生修改的正文。修改前版本与已删除内容不能新建批注。实时预览的当前内容可批注。
2. 普通文字仅支持段落内选区。跨段落选区不能静默截断。允许重叠批注，点击重叠位置时列出关联线程。论文公式按完整公式节点批注，不支持公式内部字符选区。
3. 选择文字后提供新建批注入口。批注线程包含初始批注和回复，支持新建、回复、编辑、删除、解决、重新打开。已解决线程仍可查看。
4. 作者包含显示名称与身份类型（用户、智能体）。内容分类为问题、建议、说明。无需账户登录；当前审阅者可管理全部批注。作者标签表示来源，不构成身份认证。
5. 变更句上的批注显示于对应变更侧栏卡片。未变化正文使用独立批注卡片。总览可打开线程，并定位正文及侧栏卡片。
6. 总览默认按正文位置排序，支持创建时间与更新时间排序。筛选包含作者身份、内容分类、解决状态、定位状态；支持搜索与上一条/下一条浏览。
7. 同一论文项目的不同报告与实时预览共享批注。线程记录所属内容版本，不能把旧批注误挂到其他版本的内容。共享数据需要磁盘存储，不能仅依赖 localStorage 或整份报告指纹。
8. 每个线程保留创建时原文和历次关联快照。只有关联内容变化时增加历史记录。侧栏默认显示创建时原文及当前内容；关联历史折叠展示。
9. 源码更新后尝试精确及模糊匹配。高可信、唯一候选可以自动迁移，模糊迁移显示“自动迁移”。多个相近候选或低可信匹配标为“待重新定位”，提供候选及手动关联入口。原文被删除时，仍保留原文和线程。手动关联也保留历史。
10. 实时预览页面刷新后保留线程和编辑草稿。正在输入的批注不能因源码保存而丢失。
11. 智能体通过命令行或结构化接口读取正文与线程、定位选区、创建批注、回复并管理线程。无需在报告内新增调用智能体的审阅按钮。
12. 分享报告携带批注。接收者可继续批注。离线报告使用浏览器存储，并支持携带最新批注的 HTML 导出及 JSON 导入、导出备份。导入相同线程不能重复创建；出现冲突不能静默丢失内容。
13. 批注正文支持纯文本与 LaTeX 行内、块级公式，复用现有公式渲染能力。渲染失败时保留可读原文。用户输入不能作为任意 HTML 执行。

## 现有架构约束

- `preview.py` 渲染正文节点与部分变更句子的标识。
- `report_interaction.js` 管理变更卡片的页边展示与定位。
- 无标签段落的节点标识会随正文改变，不能用它作为唯一长期锚点。
- `live.py` 重建报告，`live_reader.js` 在版本更新时整页刷新。
- `report_reader.js` 的审阅记录按报告指纹保存，不能直接承担跨报告批注存储。
- `serve.py` 已有本机服务请求验证；批注接口复用现有服务边界。
- `agent_tools.py` 已有报告查询工具；批注接口应保持项目现有命令风格。
- 公式渲染会改写 MathJax 内部 DOM。公式锚点应使用完整节点及原始 LaTeX。

## 分阶段实现与验收

### 阶段 1：数据、定位与智能体接口

负责批注数据契约、项目共享存储、原子写入、版本与选区锚点、精确/模糊匹配、关联历史、CLI 与本机 HTTP API。

验收包含：线程与回复生命周期、作者与分类、项目/版本隔离、精确及模糊定位、重复文本与低可信候选不误迁移、原文删除后保留、手动关联历史、持久化和并发写入、CLI/API 读写及输入验证。提供明确接口供后续阶段使用。

### 阶段 2：报告交互

负责普通报告中的选区入口、正文标记、重叠线程、线程编辑及回复、公式批注、变更侧栏集成、独立卡片、总览排序筛选与导航。

验收使用真实浏览器，覆盖段落内/跨段落选区、重叠选区、变更句与未变化正文、旧侧禁用、线程生命周期、公式成功/失败、筛选导航、窄屏与现有阅读功能回归。

### 阶段 3：实时预览与报告交付

负责预览刷新后的草稿及线程恢复、自动迁移与待重新定位界面、原文与关联历史、项目共享、离线存储、JSON 导入导出和携带最新批注的 HTML 导出，以及用户/智能体文档。

验收覆盖：编辑草稿期间修改源码、段落移动/编辑/删除、重复内容与手动关联、不同报告共享、离线重开、导出再打开、重复导入及冲突、报告重新生成与端到端回归。

## 协调规则

- 子对话按三个阶段顺序执行。前一阶段通过主对话验收后才启动下一阶段。
- 子对话使用 `gpt-6.1-sol`、`low`。当前创建工具没有速度参数，不能通过该工具强制设置标准速度。
- 子对话只在任务完成或无法继续时向主对话发送消息。用户已直接授权这一回报。
- 子对话可在自己的对话内正常显示进度，但不得向主对话发送过程消息。
- 各阶段明确文件所有权；不得撤销用户或其他代理的改动。遇到实现边界问题先进行仓库调查，常规技术选择由实现者处理；只有影响本规格的变更才提交主对话。
- 不推送、不合并、不部署。主对话负责阶段验收和后续分发。
